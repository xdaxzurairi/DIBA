## 2026-08-11 - pwa_eworks: Bawa Fitur Upload Gambar Kerosakan dari ea_newv3

### Session summary
Abam minta fitur upload gambar kerosakan (3 slot Kamera/Galeri, disimpan pada kolum `wr.foto1/foto2/foto3` yang dikongsi antara ea_newv3 dan pwa_eworks) dibawa masuk ke pwa_eworks — sistem yang sebelum ini langsung tiada keupayaan lampir gambar semasa hantar aduan. Kerja dijalankan mengikut plan yang diluluskan Abam (`calm-forging-hartmanis.md`), diteruskan secara autonomous merentasi beberapa sesi (context di-compact sekali di tengah kerja), dan disiapkan sepenuhnya pada sesi ini — semua 11 task selesai.

### Key decisions
- Endpoint AJAX diletak dalam folder `api/` (bukan `ajax/` macam ea_newv3) — ikut konvensyen sedia ada pwa_eworks yang dah ada ~30 endpoint dalam `api/`.
- `includes/foto_upload_ui.php` dibina guna CSS custom sedia ada `form_aduan_inisiatif.php` (kelas `.form-group`, `.section-title`, CSS variables) — BUKAN Tailwind literal walaupun plan sebut "versi Tailwind", kerana borang sasaran sebenarnya guna sistem CSS custom, bukan Tailwind. Keputusan diambil selepas baca fail sebenar — intipati plan ("jangan copy Bootstrap terus") tetap dipenuhi.
- `paparan_lengkap_aduan.php` (yang sebenarnya guna Tailwind) papar gambar melalui `api/foto.php?wr_id=...&idx=N`.
- MinIO client (`includes/S3.php`, `includes/minio.php`) disalin/adaptasi dari ea_newv3, dengan `MINIO_KEY_PREFIX = 'pwa_eworks/'` supaya key tak konflik dengan objek ea_newv3 dalam bucket sama. Fallback simpan lokal ke `uploads/wr/` automatik jika MinIO gagal/tiada config — submission aduan tak sekali-kali gagal sebab isu storan gambar.
- Flow "Kembali untuk Edit" (cancel_preview) pada borang berbilang langkah turut diselaraskan supaya foto yang dah diupload tidak hilang bila pengguna klik kembali — tambah hidden fields `pv_foto_0/1/2` dan wire ke handler.
- Credential MinIO: Abam pilih guna server MinIO sama macam ea_newv3 (tag "Dev/Training" dalam `.env` ea_newv3) — nilai disalin terus ke `.env` pwa_eworks tanpa dipaparkan dalam chat.

### Fail baru
- `includes/S3.php`, `includes/minio.php` — MinIO client (AWS SigV4 self-contained)
- `api/upload_foto.php` — upload + compress (GD, target <1MB) ke `uploads/temp/`
- `api/foto.php` — serve gambar akhir (wr_id+idx) dari MinIO/lokal
- `api/foto_temp.php` — serve preview sementara (ikat session token)
- `includes/foto_upload_ui.php` — UI 3-slot Kamera/Galeri
- `assets/js/foto-upload.js` — logik upload/preview/remove client-side
- `uploads/` (folder + `.htaccess` + `temp/`, `wr/`)

### Fail diubah
- `form_aduan_inisiatif.php` — sisip UI upload, foto dibawa dalam session preview & flow "Kembali untuk Edit", thumbnail pada skrin pengesahan, load `foto-upload.js` via `$extraJS`, `clearAllInputs()` turut padam slot foto
- `api/insert_aduan.php` — fungsi `simpanFotoDB()` dipanggil selepas commit (try/catch berasingan — kegagalan foto tak jejaskan aduan)
- `includes/paparan_lengkap_print_body.php` — seksyen baru "GAMBAR KEROSAKAN" (papar jika ada foto1/2/3)
- `.env` — tambah `MINIO_ENDPOINT/ACCESS_KEY/SECRET_KEY/BUCKET/REGION/USE_PATH_STYLE`

### Verifikasi dibuat
Semua 10 fail PHP baru/diubah + `foto-upload.js` lulus semakan sintaks (`php -l` dan `node --check`) tanpa ralat.
