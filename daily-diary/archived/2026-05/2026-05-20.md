## 2026-05-20 (Petang - 16:56) - eWorks kemaskini.php — Fix 500 + Background Redirect Optimisation

### Session summary
Aduan kemaskini dalam sistem eWorks (pwa_eworks) mengalami HTTP 500 dan kelambatan teruk semasa status bertukar. Root cause: `createStatusUpdateNotifications()` — INSERT besar dengan NOT EXISTS subquery merentasi `afm_users` — dijalankan secara synchronous sebelum redirect. Diselesaikan menggunakan `fastcgi_finish_request()` pattern: browser terima redirect serta-merta, PHP teruskan notifikasi dan email di belakang tanpa blok UI.

### Key decisions
- Gunakan `fastcgi_finish_request()` sebagai penyelesaian background async — sesuai untuk PHP-FPM, tiada perlu queue/worker
- `session_write_close()` mesti dipanggil SELEPAS set `$_SESSION['flash_toast']` dan SEBELUM `header()` — tertib wajib
- `$statusChanged` flag ditambah — skip `createStatusUpdateNotifications` jika status tidak bertukar, elak kerja sia-sia
- `sendStatusChangeEmail` diberi early return guard bila SMTP tidak dikonfigurasi — skip semua DB query dalaman
- `static $checked` dalam `ensureUserNotificationsTableExists` — DDL syscat query hanya dijalankan sekali per request
- Timeout SMTP dikurangkan 15s → 5s dalam `sendSmtpAuthMail`
- Batch SQL validation (subquery dalam SELECT tanpa FROM) ditinggalkan — tidak disokong dalam MSSQL/PDO config ini
- Rollback penuh (`git checkout --`) dilakukan dua kali apabila perubahan query menyebabkan PDOException
- Commit: `cd0d015` — hanya staged `kemaskini.php` dan `includes/functions.php`
