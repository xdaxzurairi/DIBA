## 2026-05-07 (Petang) - eWorks: Lanjutan Debug SQL — bl_name, bldg_id, STRING_AGG

### Session summary
Sambungan debug SQL query BOM email. Fokus sesi ini: join table `bl` untuk nama bangunan, handle `bldg_id` dalam `EM_BOM` (BOM spesifik per building vs semua building), dan fix STRING_AGG untuk gabung semua email BOM dalam satu row. Terjumpa isu format `bldg_id` berbeza antara `EM_BOM` (B0135) dan `bl.bl_id` (B0135A) — diselesaikan dengan LIKE join.

### Key decisions
- JOIN `bl` guna `bl.bl_id = w.bl_id` untuk dapat `bl_name`
- `EM_BOM.bldg_id` adalah prefix — join guna `w.bl_id LIKE eb.bldg_id + '%'`
- BOM dengan `bldg_id = NULL` bermakna cover semua building dalam zone
- BOM dengan `bldg_id` spesifik bermakna cover building tersebut sahaja
- Logik betul: BOM NULL + BOM spesifik **kedua-dua** patut dapat email untuk building spesifik
- `eb.bldg_id` dibuang dari GROUP BY — supaya STRING_AGG boleh gabung semua email
- Filter `e.EMAIL IS NOT NULL` dibuang — semua WR disertakan, BOM_EMAIL NULL kalau tiada BOM

### Fail yang diubah
- Tiada — sesi analisis dan debug SQL sahaja

### Follow-ups
