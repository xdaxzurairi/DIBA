## 2026-09-23 - CR eWorks: Fix Paparan Laporan Bertukar ke "BPF Negeri" Selepas Pindah Kampus

### Session summary
Abam laporkan 2 staf Shah Alam (Mohd Fairuz Bin Mat Yusof - 195795, Nor Hamy Bin Sulaiman - 266718) — paparan laporan eWorks mereka bertukar ke "Laporan BPF Kampus Negeri" selepas dipindahkan ke Shah Alam. Root-cause disiasat dari kod terus (bukan tekaan), disahkan dengan data PROD sebenar, dan dibetulkan.

### Root cause
- `$_SESSION['group_3']` (peringkat akses eWorks) datang terus dari kolum `afm_users.group_3`, di-set semasa login (`portalFMS/login.php:162`).
- Dalam `menu.php`: tab **"Bahagian"** (`lap_list_bahagian`) cuma muncul untuk `group_3` = 0,1,2,3,5,6 — **TIDAK untuk 4**. Tab **"BPF Kampus Negeri"** pula muncul untuk 1,3,4,5,8,9.
- Selepas pertukaran kampus, rekod `cf`/`afm_users` kedua-dua staf dikemaskini ke Shah Alam (`site_id=B01`, `ew_bahagian=BOB`) tapi `group_3` jatuh ke **4** — memadankan majoriti Section Leader B01 lain (disahkan via query peer `role_name LIKE 'SECTION LEADER%'` — beratus rekod `group_3=4` merentas semua kampus), tapi bukan nilai yang beri akses tab "Bahagian" yang mereka jangka.
- Abam sahkan: staf ni memang baru "tukar" (pindah) ke Shah Alam — punca group_3 tersalah set semasa proses pertukaran.

### Fix
- `UPDATE afm_users SET group_3='6' WHERE user_name IN ('195795','266718') AND group_3='4'` — dijalankan terus di **FMSPROD** (host `10.0.36.128`, sebab hostname `dbprodfms36128` tak resolve dari PC pejabat — guna IP terus, disahkan reachable via `Test-NetConnection -Port 1433`).
- Disahkan `rows affected = 1` setiap satu, dan nilai selepas = 6.
- Abam minta staf logout & login semula (group_3 di-cache dalam session, hanya refresh lepas login baru) — **disahkan betul selepas login semula**.

### Nota teknikal penting (untuk rujukan CR akan datang)
- Akses Bash/PowerShell terus ke DB PROD dari sesi Claude Code disekat oleh auto-mode classifier (walaupun read-only SELECT, walaupun user dah approve dalam chat) — kena minta Abam run skrip PHP CLI sendiri di PC yang boleh reach network DB.
- `dbprodfms36128` kadang tak resolve DNS pendek dari PC pejabat — guna IP `10.0.36.128` terus sebagai fallback (disahkan boleh reach port 1433).
- **Nilai `group_3` yang relevan (dari observasi data prod):** 4 = Section Leader biasa (akses terhad, tiada tab Bahagian); 6 = Section Leader dengan akses tab Bahagian penuh. Majoriti staf guna 4; 6 jarang. Berguna untuk diagnosis kes serupa (staf pindah kampus, akses laporan hilang/berubah).

## 2026-09-23 (Sesi Kerja) - Semakan KKP 2026: Fix Nama Bangunan Kosong & Susunan Tarikh dalam Excel Export

### Session summary
Abam laporkan (via screenshot) dua isu pada laporan "Komen dan Cadangan > Senarai Komen Responden Mengikut Soalan" dalam sistem Semakan KKP 2026 (projek `webs/prestasi2`, host `10.0.36.127` = dev, `10.0.36.150` = production): (1) lajur "Nama Bangunan" kosong dalam Excel export, (2) persoalan sama ada data disusun ikut tarikh respon. Root cause dikenal pasti dan dibetulkan di kedua-dua persekitaran; satu pembetulan tambahan (susunan tarikh pada paparan skrin) di-undo semula atas arahan Abam.

### Key decisions
- Punca "Nama Bangunan" kosong: `senarai_komen_excel.php` hardcode `'' as "Nama Bangunan"` — tiada join ke jadual `bldg` langsung (beza dengan `senarai_komen.php` paparan skrin yang dah join betul dengan `bl_name`).
- Fix: tambah `left join bldg e on b.bldg_id COLLATE SQL_Latin1_General_CP1_CI_AS=e.bldg_id COLLATE SQL_Latin1_General_CP1_CI_AS` + select `e.bl_name as "Nama Bangunan"`, ikut pattern COLLATE sedia ada dalam `senarai_semua_details.php`. Disahkan berfungsi dengan uji query terus terhadap DB dev (`FMSDEV` di `10.0.36.97`) guna PHP CLI — bukan sekadar anggap betul.
- Tambah `order by b.tarikh asc` pada Excel export (fail ini generate terus, bukan lalui paging, jadi ORDER BY selamat ditambah terus).
- Isu susulan: paparan skrin (`senarai_komen.php`) pula tersusun ikut abjad kod bangunan (A0132 dulu, baru B0101) sebab `ROW_NUMBER() OVER (ORDER BY (SELECT NULL))` dalam fungsi `paged_result()` — tiada order eksplisit, ikut je rancangan join SQL Server. Dibetulkan (tambah `b.tarikh` dalam select + `ORDER BY r.tarikh ASC` dalam ROW_NUMBER) — **kemudian di-undo semula** atas arahan terus Abam ("undo"), jadi paparan skrin kekal macam asal.
- Nota proses: fail di `\\10.0.36.127` (dev) sempat disalah anggap sebagai production oleh AI sebelum Abam betulkan ("sorry itu di prod") — production sebenar ialah `\\10.0.36.150\webs\prestasi2` (disahkan via `connection_p.php` yang connect ke `FMSPROD` di host `dbprodfms36128`).

### Fail yang diubah
