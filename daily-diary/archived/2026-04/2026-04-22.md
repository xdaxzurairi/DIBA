## 2026-04-22 (11:00) - ea_newv3: Fix Submit Aduan & Upload Foto

### Session summary
Debug dan fix isu submission aduan dalam sistem ea_newv3 (eAduan v3). Punca asal: `SCOPE_IDENTITY()` return NULL kerana SQL Server triggers pada table `wr` menukar `@@IDENTITY`. Selepas beberapa percubaan (lastInsertId, OUTPUT INSERTED, T-SQL batch), penyelesaian muktamad guna `SELECT TOP 1 wr_id` lepas INSERT. Upload foto juga diimplementasi guna kolum `foto1/foto2/foto3` dalam table `wr` (file path ke `uploads/wr/`).

### Key decisions
- `SCOPE_IDENTITY()` & `lastInsertId()` tidak boleh pakai — table `wr` ada trigger yang tukar `@@IDENTITY`
- `OUTPUT INSERTED.wr_id` tidak boleh pakai tanpa `INTO` clause bila ada trigger (SQL Server limitation)
- `OUTPUT INTO @t` batch approach gagal: pdo_odbc/pdo_sqlsrv `nextRowset()` issue
- Penyelesaian muktamad: `SELECT TOP 1 wr_id FROM wr WHERE em_number/stu_id/ic_no = ? AND status='R' AND time_requested >= DATEADD(second,-60,GETDATE()) ORDER BY wr_id DESC`
- Foto disimpan sebagai file path (bukan binary) dalam kolum `foto1/foto2/foto3` — elak UCS-2 SQL Server binary encoding issue
- PDF upload diblock secara eksplisit dengan mesej spesifik

### Fail yang diubah
- `//10.0.36.127/webs/ea_newv3/pages/simpan.php` — Fix wr_id retrieval (SELECT TOP 1), tambah `simpanFotoDB` (ALTER TABLE wr, move file, UPDATE wr)
- `//10.0.36.127/webs/ea_newv3/ajax/foto.php` — Serve gambar dari filesystem `uploads/wr/` guna `wr.foto1/foto2/foto3`
- `//10.0.36.127/webs/ea_newv3/pages/detail.php` — Papar gambar dari `wr.foto1/foto2/foto3`
- `//10.0.36.127/webs/ea_newv3/ajax/upload_foto.php` — Tambah explicit PDF block dengan error message spesifik

### Follow-ups
- Test submit aduan dengan gambar untuk confirm foto tersimpan betul dalam `uploads/wr/`
- Verify kolum `foto1/foto2/foto3` auto-create berjaya dalam table `wr`

## 2026-04-22 (12:30) - Soalselidik: Fix Button Hantar Tidak Berfungsi

### Session summary
Debug dan fix button "Hantar" dalam sistem Soal Selidik Kepuasan Pelanggan UiTM yang tidak berfungsi. Ditemui 3 bug kritikal dalam `admin/db.php` dan `wizard-v2.js` yang menyebabkan submission gagal tanpa sebarang maklum balas kepada pengguna. Log `temp.txt` menunjukkan 20+ percubaan INSERT hari ini (12:05) tanpa satu pun berjaya.

### Key decisions
- `DB::commitTransaction()` tidak wujud — PHP 7 throw `Error` (bukan `Exception`) yang tidak ditangkap oleh `catch (Exception $e)` → script mati selepas INSERT, tiada JSON response
- `DB::rollTransaction()` ada `die()` sebelum log exception dan sebelum echo response — menyebabkan AJAX terima response kosong dan `swal.fire` tidak dipanggil
- `DB::getExecute($SQL, $params)` — parameter `$params` senyap diabaikan kerana signature hanya satu parameter, nilai INSERT tidak dibound ke query
- Button disable-selepas-klik ditambah untuk cegah 20+ duplicate submission serentak

### Fail yang diubah
- `//10.0.36.150/webs/soalselidik/admin/db.php` — Tambah `commitTransaction()`, fix `getExecute()` terima `$params`, buang `die()` dari `rollTransaction()`
- `//10.0.36.150/webs/soalselidik/submit_form.php` — Pindah `debug_log('Exception:...')` ke sebelum `rollTransaction()` supaya error sentiasa dilog
- `//10.0.36.150/webs/soalselidik/assets/app/custom/wizard/wizard-v2.js` — Disable button selepas klik, tambah `dataType:'json'`, tambah error handler dengan Swal, handle response `success:false`

### Follow-ups
- Monitor `temp.txt` untuk confirm "Berjaya" muncul pada submission berikutnya
- Boleh pertimbang hapus log debug dalam `submit_form.php` bila production sudah stabil
