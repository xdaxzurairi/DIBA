## 2026-04-21 (Petang) - pwa_eworks: Bug Fix Default Status Filter & Pagination

- `skipSection` dalam count query diselaraskan dengan data query (sebelum ini berbeza)

### Fail yang diubah

  1. Data restrict: `IN ('R','I','WC')` → `IN ('R','WC') OR (I AND crisis_mark AND NOT EXISTS wrcf)`
  2. Count restrict: sama seperti data restrict
  3. Data status filter: tambah handler `strtolower === 'all'` → skip filter (fix Keseluruhan = 0)
  4. Count status filter: sama tambah handler `all`
  5. `$countSkipSection` diselaraskan dengan `$skipSectionFilter` data query
- `includes/filter_builder.php` — restrict dalam `buildComplaintWhere` dikemaskini sama (R+WC+I2)
- `complaints.php` — kemaskini comment sahaja (logic sudah betul)

## 2026-04-21 (Petang Lanjut) - pwa_eworks: Filter Count Query & Date Range Fix

### Session summary
Sambungan sesi sebelum — Abam laporkan jumlah count tidak reflect filter seksyen kerosakan (1,726 walaupun filter dipilih, data kosong). Ditemui bahawa count query dalam `getComplaints` tidak apply 5 filter: seksyen_kerosakan, prob_type, prob_group, bldg_id, bl_id. Selepas fix, audit penuh dibuat dan julat tarikh diperbaiki untuk handle DATETIME column dengan betul.

### Key decisions
- Count query MESTI apply filter yang sama dengan data query — sebarang beza menyebabkan mismatch pagination
- Date filter guna `CONVERT(DATE, ?, 23)` + `DATEADD(day, 1, ...)` untuk include rekod sepanjang hari dateto
- `skipSection` dalam count query diselaraskan (tambah prob_type, seksyen_kerosakan, prob_group)
- Audit lengkap: semua 11 filter UI kini selaras di ketiga-tiga layer (parse / data / count)

### Fail yang diubah
- `includes/functions.php` — 3 fix:
  1. Tambah 5 filter missing dalam count query: seksyen_kerosakan, prob_type, prob_group, bldg_id, bl_id
  2. `countSkipSection` dikemaskini sama dengan data query skipSection
  3. Date filter (data + count): guna `CONVERT(DATE,?,23)` dan `< DATEADD(day,1,...)` untuk dateto

### Follow-ups
- Test semua kombinasi filter di browser
- Semak `getComplaintTotalsFromList` (index.php dashboard) — mungkin perlu audit sama
