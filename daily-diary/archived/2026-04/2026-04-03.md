## 2026-04-03 (22:40) - Security Hardening: SQLi Mitigation + Info Leakage Control

### Session summary
Jalankan audit keselamatan pada modul PWA eWorks dengan fokus SQL injection dan kebocoran maklumat teknikal. Ditemui fail legacy `input.php` guna SQL concatenation secara meluas serta endpoint API yang memaparkan error dalaman. Hardening dibuat pada lapisan input, response header, dan endpoint diagnostic.

### Key decisions
- Terapkan sanitasi ketat token/kod input dalam `input.php` (whitelist regex + SQL escaping fallback) sebagai mitigasi segera untuk kod legacy.
- Kuatkuasakan security headers secara centralized dalam `config/config.php` termasuk CSP, nosniff, frame protection, referrer-policy, dan HSTS (jika HTTPS).
- Tutup endpoint diagnostic sensitif (`api/check_em_email.php`) di production dan wajibkan login ketika development.
- Kurangkan kebocoran debug di `api/dropdown.php` dengan error message generik di production.
- Tambah client-side deterrence untuk inspect (mute console + block shortcut lazim) di `includes/head.php` untuk production.

### Fail yang diubah
- `input.php` — tambah `escapeSqlString()` + `sanitizeToken()`; harden semua input user sebelum digunakan dalam SQL concatenation; buang debug HTML comment.
- `config/config.php` — tambah `applySecurityHeaders()`, disable `expose_php`, cookie secure auto-detect HTTPS.
- `api/dropdown.php` — disable verbose error di production, generic 500 response.
- `api/check_em_email.php` — block endpoint di production (404) + require auth pada development.
- `includes/head.php` — mute console output dan tambah anti-inspect deterrence ringan untuk production.

### Follow-ups
- Refactor penuh `input.php` ke prepared statements (PDO/Database wrapper) untuk hapus SQL concatenation legacy.
- Buat allowlist CORS domain sebenar (ganti wildcard `*`) untuk API production.
- Audit fail JS lain yang masih guna `console.log` dan standardize debug guard berasaskan `DEVELOPMENT`.
