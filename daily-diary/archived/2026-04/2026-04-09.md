## 2026-04-09 (Pagi - 09:00) - Fix Notifikasi Status R & Setup Push Notifications

### Session summary
Sesi hari ini menyelesaikan isu senarai notifikasi status R yang tidak terpapar dalam panel "Aduan Terbaru". Tiga bug kritikal ditemui dan diperbaiki. Selepas itu, setup push notification pipeline untuk lock screen, app icon badge, dan notification pop-up Android.

### Key decisions
- Tambah `filter_builder.php` include dalam semua API yang guna `isCurrentUserDFMS()` dan `buildUserScopeFilter()`
- Buang date filter 30 hari pada `w.date_requested` dalam seed dan fallback — supaya WR lama status R tetap terpapar
- Betulkan parameter order dalam Step 2 seed: `[userId, ...filterParams, userId]` bukan `[...filterParams, userId, userId]`
- Guna `COLLATE DATABASE_DEFAULT` untuk resolve collation conflict antara `push_subscriptions` dan `afm_users`

### Fail yang diubah
- `api/get_notifications.php` — Tambah `filter_builder.php`, betulkan param order seed Step 2, buang date filter 30 hari Step 2 & Step 3, tambah debug info sementara (kemudian dibuang)
- `api/get_unread_count.php` — Tambah `filter_builder.php`, betulkan seed guna scope filter, tukar count kepada query tepat yang JOIN `wr` table dengan scope filter
- `includes/push_notification_sender.php` — Tambah `COLLATE DATABASE_DEFAULT` pada semua perbandingan `ps.user_id` dengan tabel sistem (afm_users, user_kampus, user_section, user_probgroup, cf)
- `C:\Users\BSM\AppData\Local\Temp\run_eworks_push.bat` — Wrapper batch untuk Scheduled Task

### Root causes ditemui
1. **`filter_builder.php` tidak di-include** → `isCurrentUserDFMS()` undefined fatal error
2. **Parameter order salah** dalam seed SQL: `$userFilterParams` dimasukkan sebagai param pertama tapi SQL expect `userId` dulu → seed gagal senyap
3. **Date filter 30 hari** pada `w.date_requested` → WR Permohonan lama (>30 hari) tidak muncul
4. **Collation conflict** `SQL_Latin1_General_CP1_CI_AS` vs `SQL_Latin1_General_CP1_CS_AS` → push notification query gagal

## 2026-04-09 (Petang - 16:00) - Audit Performance & Optimization Production

### Session summary
Sesi kedua hari ini menyelesaikan audit performance menyeluruh untuk semua fail PHP dan JS dalam pwa_eworks. Semua 8 task performance ditemui dan diperbaiki tanpa menjejaskan flow sistem.

### Key decisions
- Replace `cloneNode + replaceChild` dengan stored `_pushBtnClickHandler` ref — elak expensive DOM replace setiap kali state bertukar
- Replace `setInterval` dalam `animateNumber` dengan `requestAnimationFrame` — animasi synced dengan browser paint
- Guna `DocumentFragment` untuk batch DOM insert dalam `updateRecentComplaints`
- Debounce `resize` event dalam sidebar (150ms) — elak beratus panggilan semasa drag resize
- Tambah TTL 5 minit pada dynamic SW cache — API responses tidak serve stale data bila offline

### Fail yang diubah
- `assets/js/push-notifications.js` — Disabled-state cloneNode diganti dengan `_pushBtnClickHandler` pattern; `console.*` ditukar ke `__log/__warn/__error`
- `assets/js/dashboard.js` — `setInterval` animateNumber → `requestAnimationFrame`; `forEach appendChild` → `DocumentFragment`
- `assets/js/sidebar.js` — `resize` event wrapped dengan debounce 150ms
- `sw.js` — Tambah `DYNAMIC_CACHE_TTL` (5 min); `networkFirst` simpan `sw-cache-timestamp` header dan semak TTL sebelum serve dari cache

### Follow-ups
- Pengguna masih perlu subscribe push notification pada telefon
- Verify Scheduled Task masih berjalan selepas reboot BSM server
